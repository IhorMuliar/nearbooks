NEAR's Supply Still Outruns Intents Revenue

Every day a pinned worker running inside an Intel TDX enclave reads NEAR mainnet at the first block of the UTC day and writes what it finds to the nearbooks.near contract. This page reads those entries from the chain and re-checks each one in your browser while you read.

The Latest Entry

Each entry compares the first block of a UTC day with the first block 28 days earlier. There is one entry per day; the first valid one wins and it is never edited.

    Open Predictions

    Four claims were written to the contract with a resolve date and can't be edited. Only the attested entry for that exact date decides each one: confirmed, refuted, or void if the entry lacks the metric. Anyone can call resolve_prediction once the date has an entry.

      How to Check It

      Three parties touch each number, and each step leaves something you can check without trusting this page.

      1. The enclave reads mainnet. A worker whose sha256 is pinned in the contract runs inside OutLayer's Intel TDX enclave. It reads total supply, the three Intents revenue wallets and a reserves check on intents.near, and prints JSON.
      2. The contract stores it. nearbooks.near accepts output only from the configured OutLayer contract, for the pinned build, answering a request it made. Changing the pin waits out a timelock and never touches a date that has already begun.
      3. Your browser re-checks it. This page runs the seven checks in section 1. The Python script below also verifies the TDX quote against Intel's root of trust.

      What "verified" tells you

      The numbers came from the build this repository publishes, and the contract had pinned that build for the date. OutLayer attests that it ran on exactly that input and produced exactly these bytes. The run was requested through nearbooks.near rather than handed in by someone else.

      What it doesn't tell you

      It doesn't tell you that Intel TDX and OutLayer are honest: this page trusts their attestation, and only the script checks the quote itself. Nor does it tell you that the RPC answers were true mainnet state. The worker reads over JSON-RPC without state proofs, though the evidence hash commits to the raw responses. And it says nothing about whether the predictions are right; they are claims waiting for a date.

      Re-run it on your machine

      The first command rebuilds every historical finding offline. The second checks an attested entry, including the TDX quote.

      git clone https://github.com/IhorMuliar/nearbooks
cd nearbooks && make verify
      python3 -I contract/scripts/verify_attestation.py nearbooks.near
