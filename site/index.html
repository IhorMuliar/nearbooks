    Open predictions

    on-chain

    Each claim was written to the contract with its resolve date and can't be edited. Only the attested entry for that exact date decides it: confirmed or refuted, or void if the entry lacks the metric. Anyone can call resolve_prediction.

    How to check it

    on-chain

    Three parties touch each number. You don't need to trust this page: every step leaves something you can check.

    1. The enclave reads mainnet

      A worker whose sha256 is pinned in the contract runs inside OutLayer's Intel TDX enclave. It reads total supply, the three Intents revenue wallets and an intents.near reserves check.

    2. The contract stores it

      nearbooks.near accepts output only from the configured OutLayer contract, for the pinned build, answering its own request. Changing the pin waits out a timelock.

    3. Your browser re-checks it

      This page compares the worker hash, the pin, OutLayer's attestation and the transaction. The Python script also verifies the TDX quote against Intel.

    What verified tells you

    • The numbers came from the build this repository publishes, and the contract had pinned that build for the date.
    • OutLayer attests that the build ran on that exact input and produced exactly these bytes.
    • The run was requested through nearbooks.near, not supplied by someone else.

    What it doesn't tell you

    • That Intel TDX and OutLayer are honest. This page trusts their attestation; the TDX quote itself is checked only by the script.
    • That the RPC answers were true mainnet state. The worker reads over JSON-RPC without state proofs; the evidence hash commits to the raw responses.
    • That the predictions are right. They are claims waiting for a date.

    Re-run it on your machine

    Rebuild every historical finding offline, then check today's attestation, including the TDX quote.

    git clone https://github.com/IhorMuliar/nearbooks
cd nearbooks && make verify
    python3 -I contract/scripts/verify_attestation.py nearbooks.near

    What would make supply shrink?

    Supply shrinks only if the NEAR bought back each day is burned and exceeds the NEAR issued each day. The defaults are today's measured values; move the sliders to test a scenario.
