## Keeper

`keeper/keeper.py` (standard library only) runs once per UTC day, from `.github/workflows/keeper.yml` at 00:20 UTC or by hand:
1. It checks its own key on chain and refuses to run unless the key is a function-call key for this contract, limited to `keeper_request_snapshot` and `resolve_prediction`.
2. For today, and for any earlier resolve date of a Pending prediction, it skips dates that already have an attested snapshot. For each remaining date it finds the first mainnet block at or after 00:00 UTC of the date and of 28 days earlier (binary search over mainnet RPC with backoff). It checks the contract's budget and daily cap, calls `keeper_request_snapshot(date, B, B28)` and waits for the attested result.
3. It calls `resolve_prediction` for every Pending prediction whose `resolve_after` now has an attested snapshot.

It logs JSON lines. `--dry-run` (`make keeper-dry`) plans without a key and signs nothing. A second run on the same day does nothing.

**Why its spending is bounded.** A NEAR function-call access key cannot attach a deposit. The testnet run checked this: the payable `request_snapshot` with a deposit was refused with `DepositWithFunctionCall`. So the keeper cannot pay OutLayer itself. The contract holds a prepaid budget instead:
- anyone can fill it with `fund_keeper`,
- only the account the owner names with `set_keeper` may draw from it, through the non-payable `keeper_request_snapshot`,
- each request draws exactly `min_request_deposit()` (0.03 NEAR), and at most the daily cap per UTC day, counted gross. The cap is 0.06 NEAR here and at most 1 NEAR by contract rule.

For these requests OutLayer's payer is the contract. The callback credits the unused storage reserve back to the budget instead of sending it to the keeper. OutLayer refunds the unused part of the 0.01 NEAR run deposit with a plain transfer (0.00862 NEAR in the 2026-10-20 run). The contract cannot attribute that transfer, so it lands in the contract's free balance and the budget ledger never overstates what is there.

What the key itself can burn is capped by its 0.5 NEAR gas allowance: one snapshot request used 0.00132 NEAR of it. Its other limits were checked on testnet and refused before execution, at no cost:
- `ReceiverMismatch` for a call to another contract,
- `MethodNameMismatch` for any other method,
- `RequiresFullAccess` for a transfer.

The GitHub secret `NEARBOOKS_KEEPER_KEY` holds only that key. The keeper account's full-access key never leaves the deployer's machine. In the worst case a leaked key spends the daily cap on snapshots for dates of the attacker's choosing, plus the remaining allowance as gas. It cannot move funds anywhere else.

Each stored snapshot through the keeper cost the budget 0.02102 NEAR: 0.01 sent to OutLayer plus 0.01102 NEAR of storage (1,102 bytes). After the two snapshots of 2026-10-20 and 2026-10-21 the budget holds 0.10796 NEAR. A request needs 0.03 NEAR available before the reserve comes back, so that covers four more days. The setup and the first request are in `contract/testnet-keeper.log` (`contract/scripts/testnet_keeper.sh`). Contract tests: `daily_cap_is_enforced_and_resets_the_next_utc_day`, `a_stranger_cannot_spend_the_keeper_budget`, `the_owner_cannot_spend_the_keeper_budget`, `unused_storage_reserve_returns_to_the_budget_not_to_the_keeper`, `rejected_keeper_run_returns_the_whole_reserve_to_the_budget`, `keeper_cannot_spend_more_than_the_budget`, `budget_accounting_fund_and_withdraw` and more in `contract/src/tests.rs`. Python tests in `tests/test_keeper.py` cover the RFC 8032 signing vectors, the transaction encoding, the first-block search and the run logic.

The contract-side rules (calls, events, accounting) are in `docs/attestation.md`, section "Keeper budget".

`make site` serves the page at http://127.0.0.1:8000/site/. It reads the snapshots, predictions and pin history from the testnet contract in the browser. A snapshot is marked **verified** only if all of these hold:
- its worker hash is in `contract/known_workers.json`,
- that hash is the contract's pin for that date,
- OutLayer's attestation matches the snapshot's wasm, input and output hashes,
- the attested transaction called this contract.
